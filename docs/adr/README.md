# 架构决策记录（ADR）

每个文件记录一个「为什么这么选」，包括代价和「什么时候该重新考虑」。
格式参考 Michael Nygard 的 ADR 写法，但要求多一条：**替代方案为什么没选**。

| [0005](0005-application-level-policy.md) | 策略在应用层，不做沙箱（边界明确） | 已采纳 |

## 什么时候该写新的 ADR

- 改变了一条「别人会追问为什么」的选择；
- 推翻了已有 ADR（新写一份，状态写「取代 000X」，不要改历史文件）；
- 明确决定「不做」某件事，且这件事看起来该做。

## 模板

```markdown
# ADR 000N：一句话说清决定

- **状态**：提议 / 已采纳 / 已取代 / 已废弃
- **日期**：YYYY-MM-DD

## 背景
约束是什么，不选会怎样。

## 决定
具体选了什么，包括刻意的细节。

## 后果
好处 / 代价 —— 代价必须写，不写代价的 ADR 是宣传。

## 替代方案
每个候选 + 为什么没选。

## 什么时候应该重新考虑
可观测的触发条件，不是「以后再说」。
```
