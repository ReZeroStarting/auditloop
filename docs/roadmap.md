# 路线图

> 原则：每个阶段结束时，都必须有一条**能当场跑给人看**的命令。
> 不是「做了三个模块」，是「多了一个证据」。

## P1 · 让它能用真模型干活

| 事项 | 验收标准 | 状态 |
|---|---|---|
| 真实上游跑通 | `run --verify` 在真实仓库返回 `ok` | ✅ 2026-10-31：15 步 / 18 次调用 / 1 次被拒 / `rc=0` |
| 流式输出 | 逐字打印，账本仍记完整消息 | ✅ `--stream`（SSE 解析 + 工具参数增量拼装） |
| 工具调用并发 | 同一条响应里的多个工具并行 | ⬜ 未做，仍顺序执行（换成并行会牺牲账本线性可读） |
| 预算熔断 | 超预算停手，退出码 5 | 🟡 会停手（exit 5），但没有「降级给出部分结论」 |
| 首个真实评测 | live 跑并把通过率写进 README，不美化 | ✅ live 5/5（deepseek-chat，$0.0119） |

**新增的结论**：三条失败路径用例已标为 `mock-only`——真实模型不会按剧本犯错。
这不是坏消息，是评测的边界：**通过率必须说清它测的是什么，否则会骗人。**

## P2 · 让它可靠

| 事项 | 验收标准 | 状态 |
|---|---|---|
| 子 agent 落地 | 独立上下文与独立账本，主账本有引用 | ✅ `--subagent`：独立账本、只读白名单、不可递归 |

| 失败注入测试 | 进程在临界点被 kill 后仍可解释 | 🟡 用截断账本模拟过，未做真实 kill 注入 |

## P3 · 让它像产品（2 周+）

| 事项 | 验收标准 |
|---|---|
| HTTP 层 | FastAPI（或纯标准库 http.server）+ SSE，把账本事件实时推到浏览器 |
| 预算双重闸门 | 单会话上限 + 全站日上限；到顶降级而不是 500 |
| 评测看板 | 每次改动跑 eval，结果存历史，能看「第 N 次改动后通过率从多少到多少」 |
| 长跑验证 | 连续 6 小时无人值守跑评测集，账本零丢失、零重复关闭 |
| 与 keepwatch 集成 | 长任务用 keepwatch 排队，auditloop 作为 worker 执行；交接痕迹两边都对得上 |

## 不着急做的（写下来是为了不被问倒）

- **多 agent 协作**：ClawBridge 已经覆盖了，这里不重复造。真要接，走共享目录 + 消息。
- **向量检索 / RAG**：代码搜索用 grep + glob 已经够；检索解决的是「不知道在哪」，代码场景通常知道。
- **微调**：这是运行时项目，模型能力是输入不是输出。
- **GUI 编辑器**：CLI 是这个项目最好的形态，图形化会把注意力从账本移开。
